Purpose & process

Answer: what changed in my notes, and does anything need my attention? A request produces a result; the reader scans the concrete content and its save state, then optionally opens the exact edit, the supplied text, or source details. A suggestion ends before saving. Uncertain completion directs inspection before another attempt. Multiple notes preserve independent outcomes.

The calling agent selects a faithful lead fact and relevant content. Kajamite owns the saved result and exact source values. The renderer composes them without inferring facts or treating a note’s check label as external proof. The host owns placement; the same detail body supports a sidebar or inline expansion. This read-only prototype sends no requests, saves nothing, and offers no simulated apply or undo.

Semantic tree & shared patterns

Note result ├─ What matters · concrete lead + exact excerpt / note list ├─ Save state · icon + one sentence, attached to the content └─ Inspect · one stable action ├─ Edits · unified or split line diff + word changes ├─ Read note / Read passage · supplied after-text, when available ├─ Sources · optional disclosure, when supplied └─ Source details · available through prototype controls

Small changed blocks are shown in full. Larger diffs use first/last edited regions, with fold seams that expand directly in the card. Comparisons share wrapped rows, line gutters and omission seams in cards and detail. A seam reveals supplied content in place and becomes a gutter control beside that content. Card comparisons use one bounded scroll area. A single seam expands in place while retaining its focused control and screen position; the revealed region folds through its gutter control. Long lines wrap in full without word truncation. Supplied folded content expands inline; unavailable content stays unavailable. Prose comparison treats declared soft line wraps as whitespace; reading and source views retain the exact original text. Previews retain headings and blank lines; displayed line numbers refer to supplied text. Comparison depth is controlled by scrolling and local folds. Complete supplied bodies support Read note. Source-faithful line positions appear in supplied multiline passages; normalized prose does not claim physical source line numbers. Three content patterns: edited passage, note created/removed/moved, and repeated note rows. A result with no supplied text uses the same card shell and states the known outcome. Failures and uncertainty stay at the stable surface. Optional source and protocol details remain disclosed. Scene groups organize the prototype, not the product’s operations.

Value grammar & layout

Title and location identify one note. Minus/plus rows compose an exact change; word highlights isolate edited spans. Deleted words use strikethrough; added words are highlighted without underlining. Save icon and sentence compose the outcome. Each note row keeps its title, result and action together. Green means added text or a confirmed save; red means removed text or a failed attempt; amber means attention; olive means a suggestion or selection. Text, icons, signs and positions preserve meaning without color.

Four-pixel rhythm. Type roles: 32/36 page title, 24/28 detail title, 17/24 card lead, 14/24 prose, 13/22 diff text, 12/20 secondary text, 11/16 metadata. Cards have intrinsic height. The sidebar owns one vertical scroll; text wraps. Responsive sizes retain reading order; split diff switches to unified below 560 px. Gutters number the supplied passage, never the full file unless a complete body is supplied.

Coverage & evidence

The scene library covers the current mutation-result branches and additional comparison edge cases. It does not add read/search tools or change storage semantics. Synthetic lead facts are fixture-authored; a production renderer requires caller-supplied faithful summaries or deterministic excerpts. Missing text stays missing. A successful save can lack an exact diff; an interrupted request can have saved. Source snapshots cannot establish the current external world.

Pattern references: Pierre Diffs fold separators, Zed aligned comparisons, VS Code collapsed regions, and VS Code inline and side-by-side review and GitHub unified and split review. The prototype uses line sequence comparison, word-level edits, unchanged-line disclosure, and explicit addition/removal signs. Native host placement, caller summary contracts, source integrity and live acceptance remain implementation work.
